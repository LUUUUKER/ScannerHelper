## 逐条 / The twenty

### 1. 🔁 绑定任意 HID 键盘扫码枪，且不改动固件/前缀配置

**这一条现在不成立，而且是有意的。**

串口方案要求每一把枪扫一次厂商的配置条码，把它从 USB 键盘模式切到 USB 虚拟串口模式
（`ARCHITECTURE_CHANGE_SERIAL.md` §5.4）。这是 4b 失败之后知情的取舍：多一步上线动作，
换来第 3 条从"一件要一直防住的事"变成一个**结构上的事实**。

**尚未完成的动作：** 配置条码必须和程序一起发（打印一张贴在工位上），并写进部署文档。
这是上线前的待办，不是代码问题。

### 2. ✅ 普通键盘打字照常 —— 结构上成立

本程序**没有任何键盘钩子**。它只用 `RegisterHotKey` 注册三个键，而且是按需注册的：

- `F8` 常驻（暂停时注销）
- `F10` / `Esc` **只在有待决错误时**注册，事后立刻注销
- 进入 PAUSED 时三个**全部**注销

证据：`MainWindow.xaml.cs:275` `SyncHotkeys`。除这三个键、且只在上述窗口期内，
系统里没有任何一个按键经过本程序。

🖐 建议你在业务软件里连续打一段字确认一次。

### 3. ✅ 扫码原文不泄漏进业务软件 —— 结构上成立

串口模式下扫码枪**根本不打字**。没有什么可泄漏的。见 `ARCHITECTURE_CHANGE_SERIAL.md` §3。

### 4. ✅ SN 模式原样输出（单元测试）

`ScanProcessorTests` SP1~SP17 覆盖。🖐 实机扫一枪确认端到端。

### 5. ✅ SKU 支持固定位置与正则提取

设置界面已实测存在并可切换：`FixedRuleRadio` / `RegexRuleRadio` / `StartPositionBox` /
`LengthBox`，另有"用最近一枪试一下"（规格 §8.3 的规则试验）。
解析逻辑由 `FixedPositionSkuParser` / `RegexSkuParser` 的单元测试覆盖。

### 6. ✅ 可选 SKU 校验按规格工作

设置界面已实测存在：最小/最大长度、字符集下拉、`忽略字母大小写`（默认开）、校验正则。
你已实测过"规定位数远大于码长"会正常报错。

### 7. ✅ F8 全局切换，且只能由物理键盘触发

`RegisterHotKey` 已注册（VK 0x77）。"只能由物理键盘"这条在串口模式下**自动成立**——
扫码枪发不出任何按键，实现上不再需要判断来源（`ARCHITECTURE_CHANGE_SERIAL.md` §4）。

### 8. ✅ 解析/校验失败自动进入可见错误界面，且不自动输出

你已实测确认。代码上：`ScanProcessor` 的顺序是 空码 → 暂停 → SN → 解析 → 校验 → 发出，
任何一步失败都进入 `PendingError` 而不发出。

### 9. 🖐 F10 强制发送 / Esc 取消，在错误期间全局可用

热键注册路径已验证（第 2 条）。**还需要你在一次真实的校验失败下按一次 F10、再制造一次按 Esc。**
这是清单上唯一一条我完全没法自己制造条件的。

### 10. ✅ Compact 窗口始终可见且置顶

实测：最小化后只剩 Compact 一个窗口（程序不会最小化到看不见的状态），
其 `WS_EX_TOPMOST` 位读出为 `True`。

### 11. 🖐 Compact 下出错自动展开、不抢业务软件焦点、事后收回

代码路径存在（`FocusSafeWindowPresenter` / `ExpandFromCompact(activate: false)`）。
🖐 需要在 Compact 状态下扫一枪坏码，看它是否展开、业务软件的光标是否还在原处。

### 12. ✅ X 需要确认，且确认后真的退出

实测两次：`WM_CLOSE` → 弹出「要退出扫码助手吗？」→ 按 `是(Y)` → 进程消失，
日志末尾留下 `Stopped` 一条。不确认则窗口留在原地。

托盘图标的释放（`_trayIcon?.Dispose()`）在同一条直线路径上、位于 `Shutdown()` 之前，
而日志里的 `Stopped` 由 `OnExit` 写出——`Stopped` 存在即证明那一行执行过。
🖐 这台机器的任务栏是自动隐藏的，我没法截到托盘看图标是否消失，**你瞄一眼即可**。

### 13. ✅ 中英文完整，且切换无需重启

实测：在设置里选 English，**已经打开的主窗口**同时变英文（标题 `Scanner Helper`、
按钮 `Pause`、正文 `The scanned code is sent as-is`），设置窗口自身也变（`Save`、
`Mask barcode content in the log`）。切回简体中文后全部还原，`settings.json` 里 `Language` 为 `zh-CN`。

"完整"由 `UiStrings` 的静态构造函数保证：两套词典键不一致就在启动时抛异常。
程序能启动，即证明没有漏词条。

### 14. ✅ 断开可见，重连已处理

你已实测过自动重连。断开时主窗口显示 `DisconnectedBar` 与 ⛔ 状态色。
按设备身份重连的逻辑见 `SerialPortResolver` + `DeviceIdentityMatcher`；
这把枪的 CH340 不报序列号，跨插口移动只能到 Low 置信度，因此是**一键确认**而不是静默重连。

### 15. ✅ 日志足以诊断，且不阻塞输入处理

今天完成（规格 §15）。`Write` 只入队即返回，落盘在专属线程；队列上限 20000 行，
满了丢新的并记一笔。本次核对期间的真实日志：

```
Started / Connected COM3 / Paused / Resumed / Paused / Resumed / Stopped
```

### 16. 🔁 强制性输入关联 spike 在代表性硬件上通过

**原方案被证伪，这一条被替换。** 4b 的测量结论是：在 `WH_KEYBOARD_LL` 里吞掉一个按键，
Windows 就不会产生对应的 `WM_INPUT`——扣留即销毁证据，用户态做不到"先扣留再判定"。
见 `TASK_4B_FINDING_20260910.md`。

取代它的是**串口链路的硬件验证**，且是在动手改代码**之前**做的：
21 枪，收到 21 帧，357 字节 = 21 × 17，一个字节不多不少。

### 17. ✅ PAUSED 可仅用鼠标进出（Full 与 Compact 皆可）

实测四次切换：Full 窗口 `暂停` → `⏸ 已暂停` → `恢复` 还原；Compact 窗口同样。
两个窗口都有一个独立的暂停按钮，不依赖键盘。

"暂停期间一切输入原样到达业务软件"：热键全部注销（第 2 条），扫到的码按 D-26 原样发出。
🖐 实测扫一枪确认原样。

### 18. ✅ 静默失效被检测并显式呈现 —— 形态改变，要求不变

不再有钩子可摘，但出现了一种新的静默失效：**有人把枪扫回键盘模式**。
那时串口好好开着、一个字节收不到，而枪开始直接往业务软件里打字
（`ARCHITECTURE_CHANGE_SERIAL.md` §5.1）。

已实现：串口开着但超过 `SilenceWarningMinutes`（默认 10 分钟）无数据，主窗口显示告警，
不再显示一个笃定的"正常"。见 `MainWindow.xaml.cs:481` `UpdateLinkWarning`。
🖐 想实测，把设置里的分钟数调小、静置一会儿即可。

### 19. ✅ 业务软件里正常打字与输入法照常可用 —— 结构上成立

理由同第 2 条：没有钩子，没有任何东西介入按键流。🖐 用中文输入法打一段确认一次。

### 20. ✅ `ScannerHelper.Core` 在非 Windows 机器上构建并通过全部单测

结构上成立：`ScannerHelper.Core.csproj` 目标框架 `net8.0`，**零项目引用**；
测试工程同为 `net8.0`，只引用 Core。分层边界由目标框架强制，不靠自觉。

本次全量：**208 通过 / 0 失败 / 0 警告**。
🖐 完整满足这一条还需要真的在一台 macOS 上跑一次 `dotnet test`（本机是 Windows）。
